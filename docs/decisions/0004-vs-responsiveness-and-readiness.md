# 0004. VS の応答性 — モーダルダイアログと準備完了の判定

- 状態: 受理
- 日付: 2026-08-25
- 検証: S1（spike/results/spike-final.json）
- 関連: design.md §10.2, §10.3, §15.1

## 発見した事実

### 1. ROT に居ることと、DTE が応答することは別である

VS は起動のかなり早い段階で `!VisualStudio.DTE.<ver>:<pid>` を ROT に登録する。
しかしこの時点ではスタートウィンドウ（プロジェクト選択画面）しか出ておらず、
**すべての DTE 呼び出しが失敗する**。`DTE.Version` すら通らない。

### 2. モーダルダイアログが出ている間、DTE は無期限にブロックされる

検証中に次の 2 つで再現した。

- コマンドラインで指定したファイルが見つからないというエラーダイアログ
- 「Visual Studio を最新の状態に保つ」という更新通知ダイアログ

どちらも VS のメインウィンドウを無効化する。この間、DTE 呼び出しは
`RPC_E_CALL_REJECTED (0x80010001)` で失敗し続ける。**60 秒リトライしても回復しない。**
ダイアログを閉じた直後、リトライ 0 回で全呼び出しが通るようになった。

### 3. メッセージフィルタは `SERVERCALL_RETRYLATER` しか救わない

`CoRegisterMessageFilter` の `RetryRejectedCall` は、設計書 §10.2 の記述どおり実装すると
`SERVERCALL_RETRYLATER` (2) しか再試行しない。しかし計測では拒否理由の内訳は
`retryLater=235, rejected=0` であり、VS は一貫して RETRYLATER を返していた。
つまり**フィルタは正しく再試行しており、それでも回復しなかった**。
VS 側がブロックされている限り、クライアント側の工夫では突破できない。

### 4. 呼び出し側のリトライも別途必要

フィルタの再試行枠（30 秒）を使い切ると呼び出しは `COMException` になる。
通常運用（ビルド中など一時的なビジー）を吸収するには、フィルタに加えて
呼び出し側でも `RPC_E_CALL_REJECTED` / `RPC_E_SERVERCALL_RETRYLATER` を待つ必要がある。

### 5. 正常時の COM 呼び出しは非常に安い

VS が応答可能な状態なら、DTE のプロパティ読み取りは **1 回あたり 0.048 ms**。
COM 越境コストは実質無視できる。

## 決定

1. `IOleMessageFilter` は `SERVERCALL_RETRYLATER` と `SERVERCALL_REJECTED` の両方を再試行する。
   後者は今回観測されなかったが、コストが無く、他の VS 状態で発生しうる。
2. 加えて、Backend の全 DTE 呼び出しを呼び出し側リトライで包む
   （`RPC_E_CALL_REJECTED` / `RPC_E_SERVERCALL_RETRYLATER` を規定時間まで待つ）。
   フィルタだけに頼らない。
3. **「VS が使える状態か」の判定を COM に頼らない。** COM が応答しない状況こそ判定したい対象であり、
   COM で判定しようとすると同じ理由でブロックされる。Win32 でプロセスのトップレベルウィンドウを
   列挙し、次を見る:
   - メインウィンドウが存在しない → 「VS が起動中、またはスタートウィンドウのまま」
   - メインウィンドウが無効（`IsWindowEnabled == false`）で、他に有効な可視ウィンドウがある
     → 「VS がモーダルダイアログを表示している」。そのウィンドウのタイトルをエラーに含める
4. この判定を `daemon.status` と `session.attach` の前段に入れ、
   ブロックされている場合は **待たずに即座に** `PRECONDITION` で返す。hint の例:

   ```
   Visual Studio (pid 12345) がモーダルダイアログを表示しているため操作できません:
   「Visual Studio を最新の状態に保つ」
   ダイアログを閉じてから再実行してください。
   ```

   30 秒黙って待ってから曖昧に失敗するより、1 秒で「何を閉じればよいか」を返すほうが、
   エージェントにとっても人間にとっても価値が高い。

## 影響

- design.md §10.2 に「メッセージフィルタ + 呼び出し側リトライ + Win32 による準備完了判定」の 3 段構えを追加する
- design.md §15.1 の `PRECONDITION` に「VS がモーダル表示中」のケースを追加する
- Phase 0 の `daemon.status` は、この Win32 判定だけなら COM 無しで実装できる
- 実運用上の注意として、VS の更新通知を無効化しておくことを README に書く
