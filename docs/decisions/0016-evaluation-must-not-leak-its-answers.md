# 0016. 評価スイートは答えとプロンプトの経路を検証する

- 状態: 受理
- 日付: 2026-08-25
- 関連: design.md §18.3, §20 Phase 3

## 発見した事実

評価スイート（`eval/run.ps1`）の 1 回目の実行は 4 件すべて PASS だったが、
記録（`eval/results/*-transcript.txt`）を読むと、測っていたものが違っていた。

### 1. 症状の文が化けて届いていた

Windows PowerShell のパイプは既定で CP932 を使う。日本語の症状文が
壊れたままエージェントに渡っていた。エージェントは自分でそう書いていた。

> ご依頼の文面が文字化けして届いていたため、症状の記述は読めませんでした。
> 実行中プロセスの状態から症状を推定して調査しています。

つまり「症状から原因に辿り着けるか」を測ったつもりで、
「症状なしで原因に辿り着けるか」を測っていた。**PASS は出たが、別の問題を解いていた。**

### 2. エージェントが正解ファイルを読んでいた

`eval/cases/BUG_NN.md` には「正解」節がある。これが調査対象と同じリポジトリにある以上、
賢い調査者ほどそれを見つける。実際に見つけていた。

> 経緯として、`eval/cases/` に仕込みバグの解答ファイルがあり、
> 対象ビルドを絞る過程でそれを読んでいます。

測っていたのは調査能力ではなく、答えの探し方だった。

## この 2 つに共通すること

**どちらも「PASS」という結果は変わらなかった。** 結果だけを見ていたら気づかない。
記録を読んで初めて分かった。

評価スイートは、道具を良くするための計測器である。計測器が別のものを測っていれば、
その数字に基づく判断はすべて狂う。しかも狂っていることが結果からは見えない。

## 決定

1. **プロンプトの経路を明示的に指定する。** `$OutputEncoding` を UTF-8 にする。
   文字コードを既定に任せない
2. **実行中は正解を作業ツリーの外へ出す。** `eval/cases` を一時ディレクトリへ退避し、
   終わったら戻す。「見ないでください」という指示は補助であって、頼りにしない。
   隠せるものは隠す
3. **記録に無効化の条件を仕込む。** 出力に「文字化け」等が現れたら、その測定を
   無効として落とす。次に同じことが起きたら、PASS のまま通さない
4. **結果だけでなく記録を読む。** 評価結果を報告するときは、
   最低 1 件は transcript を読んでから書く

## 影響

- `eval/run.ps1` に上記 1〜3 を実装した
- `eval/results/2026-08-25-v1.md` に、1 回目が無効だったことと理由を残した。
  数字だけ差し替えて黙っていると、同じ罠に後からもう一度落ちる
- design.md §18.3 に「評価スイート自体の検証」を追記する
