# 評価結果 v1（2026-08-25）

Phase 3 の完了条件（design.md §20）に対する測定。

エージェントに渡したのは **症状の文と Target の pid だけ**。SKILL.md をシステムプロンプトに付け、
Bash だけを許可した。上限 30 ターン。

**生のトランスクリプトはこのリポジトリに含めていない。** 判定・所要秒・呼び出し回数・
一致した語という測定の実質は下の表が持っている。生ログは改名前のコマンド名を含み、
書き換えれば記録として嘘になるため、載せないほうを選んだ。

## 結果

| ケース | 症状 | 判定 | 所要秒 | stakeout 呼び出し | 一致した語 |
|---|---|---|---|---|---|
| BUG_01 | 構造体の後続メンバが化ける | PASS | 189 | 20 | `nl_set_name`, `strcpy` |
| BUG_03 | 共有カウンタが飛ぶ | PASS | 80 | 11 | `nl_stray_write`, `Task_C_Main` |
| BUG_04 | 状態が 3 の次に 7 へ飛ぶ | PASS | 109 | 14 | `nativelib.c`, `nl_update_state` |
| BUG_05 | 設定読み込みで落ちる | PASS | 192 | 20 | `nl_read_config`, `nl_deref` |

合格 4 / 4。ターン上限（30）に当たったケースは無い。

同じケースを複数回まわすと所要時間は 80〜190 秒の間でぶれる。
待ちの長い操作（`wait`、条件付きブレークポイント）が時間を支配しており、
Target の実行タイミングに左右されるためである。**回数の少なさのほうが安定した指標**で、
BUG_03 の 11 回は他の 2 分の 1 以下で一貫している。

## 最初の測定は無効だった

この結果は 2 回目の測定である。1 回目には、測定そのものに 2 つの欠陥があった。

1. **症状の文が化けて届いていた。** Windows PowerShell のパイプが CP932 のままで、
   日本語がエージェントに読めない状態で渡っていた。エージェントは
   「文面が化けているのでプロセスの状態から推定する」と書いており、
   こちらが意図した「症状から調べる」経路を測れていなかった
2. **エージェントが `eval/cases/` の正解ファイルを読んでいた。**
   同じリポジトリに答えが置いてあれば、賢い調査者ほどそれを見つける。
   測っていたのは調査能力ではなく答えの探し方だった

どちらも「PASS」という結果自体は変わらなかったが、**その PASS が何を意味するかが違う**。
run.ps1 を次のように直してから測り直した。

- パイプの `$OutputEncoding` を UTF-8 にする
- 実行中は `eval/cases` をリポジトリの外へ退避する
- 出力に「文字化け」の語があれば、その測定を無効として落とす

## 読み取れること

- **4 件とも 30 ターン以内・3 分以内**で原因に到達した
- **書き込み元の特定（BUG_03）が最も安い。** 11 回。
  `find-corruption` が「静的な候補に無い書き込み」を 1 手で名指しするのが効いている。
  BUG_03 は Phase 4 で「隣接メンバへの範囲外書き込み」に変えてあり、
  ソースを grep しても見つからない種類のバグである
- **メモリ破壊（BUG_01）と状態遷移（BUG_04・BUG_05）は 14〜20 回。**
  どれも「壊れた結果」から「壊した場所」へ遡る手順が 1 段多い
- 呼び出し回数と所要時間は比例しない。待ちの長い操作が時間を支配している

## 再測定（stakeout doctor 追加後）

BUG_03 を測り直した: PASS / 152 秒 / stakeout 呼び出し 32 回。
初回（80 秒・11 回）より高い。同じケースでも 2 倍前後ぶれるので、
**1 回の測定で改善・悪化を判断しない。** 比較するなら同じ日に複数回まわすこと。

## 再現方法

```
pwsh eval/run.ps1 -Case BUG_04 -VsPid <devenv の pid> -MaxTurns 30
```

前提: `samples/target/build.ps1 -Bug <ケース名>` でビルド済み、
Visual Studio が起動していてモーダルダイアログが無いこと。

**このスクリプトは Claude Code を起動する。API の利用料がかかる。**
